# SET v0.8 execution status

## Implemented
- Supabase-backed finance summary endpoint.
- Quote/devis creation with line items, validity and deposit percentage.
- Quote → deposit-invoice conversion.
- Invoice creation with server-side totals and sequential invoice-number RPC.
- Invoice PDF/open/send actions wired into Finance UI.
- Balance fields and payment reconciliation helper.
- Stripe Billing Portal endpoint.
- Collection-action approval endpoint with ownership/audit checks.
- App Store Server integration endpoints scaffolded so entitlements are never changed from an unverified client payload.
- Business profile table for invoicing identity, VAT status, payment defaults and numbering.
- Unified entitlement table for Stripe / Apple / manual sources.
- Finance UI moved away from prompt/local-only creation to API-first behavior with demo fallback when backend is not configured.

## Deliberately gated before production
- Apple signed transaction / notification cryptographic verification requires App Store Connect issuer ID, key ID, bundle ID and private key.
- Stripe requires live/test API keys and configured Price IDs.
- Supabase migrations require a target project and service-role configuration.
- Transactional email requires a verified sender/domain in Resend (or replacement adapter).
- French tax and late-payment rules are configuration/rule-set driven and must be re-verified against official sources at release.
- Formal legal notices require explicit owner approval; SET does not auto-send them.

## Release checkpoint
Production Supabase is already bridged with migrations `set_v08_production_finance_bridge`, `set_v08_finance_rpc_hardening`, and `verify_france_2026_finance_rules`. Do **not** blindly apply legacy migrations 001–005 to the live project. Run `npm test` and `npm run build` once dependencies and deployment environment variables are available.
